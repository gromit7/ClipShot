# Обновление и аварийный откат с 0.7.0

0.6.2 обновлятора не содержит: переход на 0.7.0 выполняется один раз вручную. Далее проверка GitHub Releases через 45 секунд после запуска и каждые шесть часов. Её можно отключить в настройках. Ненавязчивое предложение; загрузка и установка по нажатию. Работа с редактором или снимком откладывает установку.

Проверяются официальный адрес gromit7/ClipShot, имя, размер и SHA-256 GitHub API. Хеш повторно проверяется перед запуском. Это доверие к HTTPS и аккаунту GitHub, не подпись издателя. Сертификата подписи пока нет; отсутствие предупреждений Windows не обещается.

После обновления программа запускается в трее. Плашка остаётся до движения мыши, затем плавно исчезает. Обновлятор сохраняет программные файлы и восстанавливает при ошибке установки или неподтверждённом запуске. Старые релизы и локальные снимки сохраняются. Пользовательская база не откатывается.

## Удалённое понижение

update-policy.json в main по умолчанию неактивен. Пример аварийной политики:

```json
{"schema":1,"channel":"stable","action":"rollback","affectedVersions":["0.8.0"],"targetVersion":"0.7.0","reason":"Исправление ошибки выпуска"}
```

Сначала проверить существующий выпуск назначения и его установщик. Затем изменить политику отдельным коммитом и отправить main. Нельзя указывать неопубликованную версию, менять файлы старого релиза или откатывать ниже 0.7.0. Только точное совпадение версии со списком разрешает понижение. Целевой релиз получаем по тегу и проверяем обычным способом. Предложение «Восстановление версии», установка по нажатию. После возврата проблемная версия автоматически не предлагается. Для снятия политики вернуть action normal и пустой список.

Обычная проверка не понижает версию. Новый исправленный выпуск должен иметь больший номер, чем проблемный. Сейчас есть стабильный канал; отдельный тестовый канал пока планируется. При несовместимой миграции базы автоматический откат требует отдельного решения и проверок.
