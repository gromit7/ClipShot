# План автоматического обновления — ещё не реализовано

Пользователь просит максимально незаметную установку новых версий и перезапуск. Это следующий этап, не функция 0.6.2.

## Сценарий пользователя

Через минуту после запуска и затем примерно раз в шесть часов приложение проверяет стабильный выпуск gromit7/ClipShot. Проверка и скачивание идут в фоне, без браузера, входа GitHub и всплывающих предложений. Предварительные выпуски пропускаются. В настройках — ненавязчивый выключатель и команда «Проверить обновления».

Если пользователь работает с окном истории, редактирует шаблон или снимок, выделяет область экрана либо идёт запись данных, установка ждёт. В безопасный момент ClipShot штатно завершает операции, закрывает базу, заменяет версию и запускается скрытым в трее. Окно на передний план не выводится; звук микрофона и назначения кнопок не меняются. Сохраняются история, шаблоны и настройки. Фоновая смена версии занимает короткое время; абсолютная непрерывность прослушивания буфера при перезапуске не гарантируется. При старте читается актуальное содержимое буфера.

## Реализация

- Метаданные: GET https://api.github.com/repos/gromit7/ClipShot/releases/latest, ETag/If-None-Match, сравнение версий и архитектуры Windows x64. Публичному репозиторию не нужен токен. Тайм-ауты и повтор с увеличением интервала; отсутствие сети не мешает программе.
- Пакет: отдельный zip обновления, update.json с версией, размером, хешами всех файлов, совместимостью и подписью манифеста. Проверка HTTPS и SHA-256 обязательна. Доверенный открытый ключ встроен в приложение; закрытый ключ подписи не хранится в репозитории и не создаётся на этом этапе. Одной суммы из того же скачанного пакета для доверия недостаточно.
- Подпись издателя Windows для исполняемых файлов — отдельное усиление доверия. При её наличии используется WinVerifyTrust. Системные защитные запросы не обходятся; обещать их полное отсутствие для неподписанного ПО нельзя.
- Загрузка в отдельную папку текущего пользователя; проверка до остановки приложения. Распаковка запрещает выход за целевой каталог, абсолютные пути, ссылки, неизвестные файлы и чрезмерный размер. Исполняется только проверенный пакет ожидаемого проекта и более новой версии.
- Маленький отдельный обновляющий процесс ждёт завершения конкретного PID и освобождения mutex. Хранит предыдущий набор файлов, меняет их атомарно, запускает новый ClipShot с флагом --background и ждёт подтверждения успешного запуска. Сам не требует прав администратора, поскольку установка пользовательская.
- При сбое запуска восстанавливается предыдущая версия. Автоматические выпуски допускают только совместимые изменения схемы данных; необратимые миграции требуют отдельной стратегии резервной копии и восстановления. Восстановление старой базы поверх уже появившихся пользовательских данных не выполняется молча.
- Версия и результат обновления доступны в настройках. Сетевые ошибки тихо повторяются; постоянная ошибка показывается без блокирующего окна. Буфер, снимки, реквизиты и идентификаторы устройств на GitHub не передаются.

## Проверки перед включением

Имитация GitHub без настоящего обновления рабочего ПК: нет сети/404/лимит API/304, неверная версия, неподходящая архитектура, незавершённая загрузка, ошибочная подпись и хеш, zip с выходом за каталог, недостаток места, занятые файлы, отключение питания между этапами, работающий редактор, успешный рестарт, авария новой версии и откат. Затем Windows Sandbox и переходы между двумя реально опубликованными версиями. До прохождения этих проверок автоматическое обновление в программу не включать.

Источники: [GitHub Releases API](https://docs.github.com/en/rest/releases/releases), [WinVerifyTrust](https://learn.microsoft.com/en-us/windows/win32/api/wintrust/nf-wintrust-winverifytrust).
