# Обновление и аварийный откат с 0.7.0

0.6.2 обновлятора не содержит: переход на 0.7.0 выполняется один раз вручную. Далее проверка GitHub Releases через 45 секунд после запуска и каждые шесть часов. Её можно отключить в настройках. С 0.7.1 обновления устанавливаются без подтверждений: окно скрыто, нет редактора, захвата, диалога или чтения буфера и прошло пять минут без мыши и клавиатуры. Проверка простоя через GetLastInputInfo; ошибка запрещает установку. Если пользователь вернулся, установка откладывается. В настройках есть необязательный режим «Только по нажатию». В автоматическом режиме предложение не показывается, только плашка после установки. Для перехода с 0.7.0 на 0.7.1 один раз нужна старая кнопка обновления.

Проверяются официальный адрес gromit7/ClipShot, имя, размер и SHA-256 GitHub API. Хеш повторно проверяется перед запуском. Это доверие к HTTPS и аккаунту GitHub, не подпись издателя. Сертификата подписи пока нет; отсутствие предупреждений Windows не обещается.

После обновления программа запускается в трее. Плашка остаётся до движения мыши, затем плавно исчезает. Обновлятор сохраняет программные файлы и восстанавливает при ошибке установки или неподтверждённом запуске. Старые релизы и локальные снимки сохраняются. Пользовательская база не откатывается.

## Удалённое понижение

update-policy.json в main по умолчанию неактивен. Пример аварийной политики:

```json
{"schema":1,"channel":"stable","action":"rollback","affectedVersions":["0.8.0"],"targetVersion":"0.7.0","reason":"Исправление ошибки выпуска"}
```

Сначала проверить существующий выпуск назначения и его установщик. Затем изменить политику отдельным коммитом и отправить main. Нельзя указывать неопубликованную версию, менять файлы старого релиза или откатывать ниже 0.7.0. Только точное совпадение версии со списком разрешает понижение. Целевой релиз получаем по тегу и проверяем обычным способом. В автоматическом режиме восстановление выполняется во время простоя; в ручном — явной проверкой из трея с последующим ожиданием безопасного простоя. После возврата проблемная версия автоматически не предлагается. Для снятия политики вернуть action normal и пустой список.

Обычная проверка не понижает версию. Новый исправленный выпуск должен иметь больший номер, чем проблемный. Сейчас есть стабильный канал; отдельный тестовый канал пока планируется. При несовместимой миграции базы автоматический откат требует отдельного решения и проверок.


Автоматический запрос завершения имеет срок действия пять секунд и повторно проверяется в UI-потоке, поэтому запоздавшая команда не закрывает новую работу. Метаданные подготовленного пакета неизменяемы; перед запуском проверяется актуальность выпуска. Обновлятор и установщик удерживают общую блокировку на время замены файлов; дочерний NSIS получает одноразовый объект передачи управления. Занятость означает отложенную попытку, не принудительное закрытие. Частичная резервная копия не считается завершённой.

## Уточнение механизма с 0.7.2

Два автоматических слота по будням: 09:00 и 15:00 местного времени компьютера. До 09 и в выходные запросов нет. Если ПК пропустил слот, выполняется одна последняя сегодняшняя проверка. Слот сохраняется до сети, поэтому ошибка, повторный запуск и перевод часов назад не вызывают новых автоматических попыток в том же слоте. Дополнительная ручная проверка запускается только по явному нажатию.

Один GET к update-feed.json в main, без перенаправлений и запасных endpoint. Обычно несколько сотен байт, максимум 32 КиБ и 10 секунд. В одной ленте стабильный выпуск и аварийное восстановление, включая размер и SHA-256. Сам установщик скачивается отдельно, только если есть подходящий новый выпуск. Перед установкой сверяется подготовленный пакет с последней успешной лентой и SHA-256 без дополнительного запроса. Если очередная проверка не удалась, автоустановка ждёт следующей успешной. Отзыв stable:null снимает предложение.

После изменения update-policy.json оператор сохраняет и отправляет её отдельным коммитом, затем выполняет scripts/Publish-UpdateFeed.ps1 -Publish. Сценарий проверяет существующие релизы и публикует общий документ. Старый update-policy.json сохраняется для 0.7.0/0.7.1. Release.ps1 автоматически обновляет ленту, сверяет её публичное содержимое и только затем заменяет локальный установщик.

Ручная проверка доступна одним нажатием в меню трея и также в настройках, без сохранения настроек. Найденный пакет загружается и проверяется; установка также ждёт безопасного простоя. Обычный фон не показывает версии и сообщения об актуальности. После успешной установки — только плашка «Программа обновлена». По явной ручной команде краткая плашка подтверждает отсутствие обновлений, готовый пакет или ошибку.
