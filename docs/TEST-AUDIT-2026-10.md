# Аудит полезности тестов — 26 октября 2026 года

Цель — проверять ошибки, опасные для данных и работы программы, а не наращивать число тестов. Просмотрены все 21 файла исходного проекта ClipShot.Checks, сценарии интерфейса и выпускной конвейер. Для обновления выполнено дополнительное независимое чтение другим агентом.

## Что убрано

Удалены 16 прежних тестовых случаев, добавлены три недостающих. Итог: 336 случаев вместо 349. Это 335 изолированных проверок и одна отдельно помеченная `Category=Hardware` проверка чтения Core Audio. Число случаев не является целью или процентом покрытия.

| Изменение | Почему это не потеря полезной проверки |
|---|---|
| Удалён `CachedRollbackCannotAuthorizeDowngradeAfterRestart` с двумя версиями | Повторял `PendingUpdateTests.CachedRollbackNeedsFreshPolicy`. Оставшаяся проверка усилена так, чтобы общий запрет понижения не маскировал отсутствие проверки разрешения отката. |
| Удалены `UnrecordedFailedRequestRemainsDue` и `DayKeyUsesLocalCalendarDate` | Повторяли уже проверенные условия предыдущего дня и формата ключа. Следующий день, длительный пропуск, выходные, старые ключи, неизвестный простой и перевод часов сохранены. |
| Удалён отдельный тест открытия пустой новой БД | Чистая база и успешное создание проверяются при начале каждого независимого сценария хранения. Сохранены повторное открытие и защита повреждённой БД от замены. |
| Удалено требование «пустая история всегда содержит ровно шесть внутренних групп» | Это внутренняя форма списка, а пользовательский контракт — отсутствие пустых разделов. Он остаётся в настоящем тесте интерфейса пустой истории. |
| Сокращены одинаковые варианты редактирования изображения | В конфликте двух записей оставлена смешанная пара «шаблон / обычная запись»: она проверяет сохранность обоих значений флага, имён, байтов и времени. Успешное редактирование именованного шаблона отдельно покрыто копированием отредактированного изображения. |
| Сокращены одинаковые отсутствующие ID и обычные промежуточные размеры | Один и тот же SQL-результат «нет такой записи» и неизменённое значение внутри допустимого диапазона не требуют нескольких одинаковых входов. Защита переполнения, неправильного ввода и ограничений размеров сохранена. |
| Удалены повторный точный поиск, пустой языковой параметр и проверка старой шутки | Остались нечувствительность к регистру, пробелы, кириллица, русский по умолчанию и явный English. Неиспользуемый текст шутки не является функцией приложения. |

В проверке розовой темы убраны повторные утверждения системной темы. Проверка каталога тем больше не требует ровно восьми записей; уникальность вариантов сохраняется. Цвета и читаемость проверяются для **всех фактически зарегистрированных тем**, включая будущие.

## Что усилено и добавлено

- `SingleSourceDoesNotIssueExtraProbeRequest` теперь считает реальные обращения к подставному HTTP-обработчику и требует ноль проб. Раньше лишний GET не приводил к отказу теста.
- `RankedMirrorIsUsedByDownloader` проверяет хост единственной полной загрузки, а не только итоговый SHA. Раньше скачивание с GitHub вместо выбранного зеркала могло пройти тест.
- `CachedRollbackNeedsFreshPolicy` использует установленную версию ниже версии кэшированного пакета: теперь удаление проверки `IsRollback` действительно обнаруживается.
- Проверка стрелки проверяет не только неизменность кончика, но и ожидаемую точку начала при горизонтальном, вертикальном и принудительном диагональном выравнивании.
- Добавлена отмена **уже начавшейся** загрузки вызывающим кодом. Синхронизация выполняется по фактическому ожиданию следующей порции байтов, без произвольного сна. Проверяются отсутствие повторов, готового EXE и оставшегося `.partial`.
- Добавлен непустой манифест, в котором исключена только обязательная DLL. Старый тест пустого манифеста не защищал от удаления отдельной обязательной записи.
- Режим `--upgrade-self-test` добавлен к проверке изоляции: нельзя допустить открытия личной истории тестовым процессом.
- Чистые SHA-тесты теперь явно отключают зеркала и задержку повторов. Все ответы и раньше были подставными; производственный список зеркал и реальные паузы между повторами здесь не требовались.

Ни одна проверка сохранности истории, шаблонов, форматов текста, атомарности редактирования, повреждения базы, SHA/размера пакета, URL, отката, докачки или прекращения повторов не удалена как «слишком дорогая».

## Проверка намеренными поломками

В отдельной копии проекта внутри рабочей папки выполнены шесть независимых мутаций. После каждой исходник копии восстановлен; рабочие исходники приложения, установленная программа и личные данные не менялись. В каждом случае TRX подтвердил именно отказ теста, а не ошибку компиляции.

| Намеренная поломка | Проверка, которая действительно отказала |
|---|---|
| Пробный HTTP-запрос при единственном источнике | `SingleSourceDoesNotIssueExtraProbeRequest` |
| Полная загрузка всегда с GitHub, игнорируя выбранное зеркало | `RankedMirrorIsUsedByDownloader` |
| Доверие старому флагу разрешения отката | `CachedRollbackNeedsFreshPolicy` |
| Удаление старых шаблонов вместе с историей по сроку | `Expiry_preserves_templates_and_recent_history` |
| Публикация установщика без проверки SHA-256 | `CorruptedDownloadIsRemovedAndNeverBecomesInstaller` |
| Разрешение манифеста без записи обязательной DLL | `ManifestCannotOmitOnlyTheDllWhileOtherHashesRemainValid` |

Результат: обнаружены все шесть внесённых ошибок. Это ограниченная ручная мутационная проверка критических сценариев, а не обещание обнаружить любую ошибку программы. Локальный отчёт: `TestResults/test-audit-mutations.json`; сценарий эксперимента сохранён в рабочей папке текущей задачи.

## Сопутствующая регрессия обновления

На этом ПК процесс 0.7.4 был запущен после неудачного обновления с флагами `--update-failed --skip-update=0.7.5`. Публичная лента при обычном запросе и запросе без кэша возвращала 0.7.5 для обеих ОС. Фильтр неудачной версии действовал и при ручной проверке, отчего клиент показывал «Обновлений нет».

В исходниках разделены ручная и фоновая команды: фон по-прежнему не запускает неудачный выпуск по кругу, явная ручная команда разрешает повторную попытку. Четыре проверки настоящего обработчика результата в синтетическом WinUI-сценарии защищают фон, ручной повтор, свежую политику отката и последующий новый выпуск. Причина самого отказа установки 0.7.5 не установлена: устранено неверное поведение проверки, а не объявлен исправленным неизвестный отказ установщика. Пользовательский экземпляр и его база не изменялись.

## Проверено и границы результата

- Финальный `dotnet test`: 336/336, без предупреждений сборки; обычное время выполнения около двух секунд на проверочном ПК.
- Восемь тем, захват и редактор прошли сценарный прогон. Синтетический WinUI-сценарий содержит 115 проверок, включая четыре новых правила повторного обновления.
- Тесты установщиков не запускались заново: алгоритмы установщика, загрузки и целостности в этой работе не менялись. Обязательный полный gate остаётся условием следующего выпуска.
- Работа на настоящей Windows 10/LTSC2019 и причина фактического отказа обновления на этом ПК остаются неподтверждёнными. Проверки с подставной сетью не заменяют испытание реальной сети.
- Опубликованные установщики 0.7.5, зеркало, лента и каталог выдачи на D не заменялись. Изменение ручного повтора предназначено для следующего выпуска.
