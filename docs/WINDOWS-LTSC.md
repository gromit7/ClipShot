# Проверка Windows 10 LTSC и Windows 11

CS-LTSC-PREFLIGHT-001. Область DIAG: только этот документ и scripts/Test-WindowsLtsc.ps1. UI, темы, manifest, зависимости и пакеты ведёт MAIN общей реализацией. Не нужны отдельные расходящиеся функции для Windows 10/11.

## Безопасный preflight

PowerShell 5.1 (проверен) или 7 (пока не проверен):

~~~powershell
./scripts/Test-WindowsLtsc.ps1 -CheckOnly | ConvertTo-Json -Depth 5
./scripts/Test-WindowsLtsc.ps1 -AppDirectory '<каталог программы>' -ProjectFile './ClipShot/ClipShot.csproj' | ConvertTo-Json -Depth 5
./scripts/Test-WindowsLtsc.ps1 -SelfTest
~~~

Обычный запуск и CheckOnly одинаково read-only. AppDirectory/ProjectFile только явные; без них не ищет программу и не читает исходник. Читаются edition/build/revision/архитектура, у EXE/DLL/PRI/Updater — версии, размер и SHA-256. Не выводятся имя компьютера/аккаунта и абсолютные пути. Никакие EXE не запускаются, процессы не завершаются, настройки/базы/шаблоны/реестр не меняются. XML проекта читается с запретом DTD и без resolver; недопустимые/неоднозначные значения отклоняются. Ошибки наружу обобщены, чтобы не раскрывать личные пути. Проверка архитектуры использует числовой код CIM процессора, а не переменную окружения, которая может отсутствовать.

METADATA_ONLY и *_RuntimeUnverified не являются обещанием совместимости. Проверка не сверяет полученные хеши с релизом и не подтверждает подпись; для опубликованного пакета есть Test-PublishedRelease.ps1. Missing-файлы показываются как MISSING. Несовпадения build/архитектуры дают OutsideDeclaredTarget; сценарий намеренно не пытается обходить ограничения.

## SDK и minimum

База ветки при подготовке: 5378f8f92bac9d31d8350b9ff6442759209f3715, ClipShot 0.7.3. В csproj TargetFramework=net10.0-windows10.0.19041.0, TargetPlatformMinVersion=10.0.17763.0 и Microsoft.WindowsAppSDK=1.8.260921001. Windows SDK 19041 задаёт доступную поверхность при компиляции, minimum17763 — заявленную нижнюю границу проекта. Это не взаимозаменяемые параметры; вызовы более новых API требуют runtime guards/fallback.

По официальной таблице Windows App SDK ветка 1.8 включает Windows 10 1809; таблица связывает её с build17763 и LTSC servicing. Это подтверждает заявленную платформенную базу, но не корректность каждого API приложения или конкретного установленного комплекта. [Windows App SDK support](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/support).

Официальная матрица .NET 10 перечисляет Windows 10 1809 Enterprise среди поддерживаемых версий; общий факт наличия Windows 10 не равен поддержке любой редакции и стадии обслуживания. Точная проверяемая зависимость ветки — .NET10, пакетные ссылки 10.0.13; таблица относится к семейству .NET10 и не является доказательством тестирования этого приложения/патча на каждом build. [Supported OS .NET10](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md).

Windows10 22H2 добавлена в тестовую матрицу как целевой сценарий пользователя; поддержку поставщика и наличие обслуживания/ESU нужно проверять отдельно. Windows до17763 и архитектуры кромеx64 в этом проекте не заявлены. Наличие self-contained runtime не добавляет отсутствующие API ОС.

## Синтетическая ручная проверка пользователем/MAIN

На разрешённой изолированной среде создать новый тестовый шаблон с заведомо вымышленным текстом, не открывая личную историю. Проверить появление раздела, выбор/копирование только этого текста и сохранение тестового шаблона. В 0.7.3 пустые разделы скрыты, hover и CatPink ещё отсутствуют: это ожидаемо для выпуска, не доказанная LTSC-регрессия. Новые функции проверить на точном следующем пакете после публикации.

Отдельные пункты будущего runtime-прогона: поиск, клавиатура/фокус, Today/Templates hover без копирования, сброс resize/drag capture после поиска (Issue8), трей, горячие клавиши, синтетический захват/редактор, темы/fallback эффектов, DPI. Не выполнять установку или реальные сценарии автоматически этим preflight. Установочные/обновляющие тесты MAIN выполняет только на синтетических данных в отдельной разрешённой среде.

## Результат тестирования сценария

SelfTest: 7 синтетических случаев платформенного классификатора (17763/19045/26100, старая ОС, ARM, нулевой build, неизвестная архитектура). Дополнительный harness проверяет XML проекта: правильный, отсутствующие поля, DTD, выражение вместо версии пакета — отказ в трёх негативных случаях. Метаданные на доступном Windows11 проверены без запуска программы. Никакой процент общей совместимости не заявляется. MAIN обновляет docs/STATUS.md после review/merge; DIAG соблюдает область двух файлов.
