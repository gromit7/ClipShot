# Онлайн-канал специалистов

Codex Работа — главный; DeepSeek — второй специалист; Codex Дача — третий удалённый.

## Устройство

Private SSH stdio MCP codex-link на личном Germany Gateway vpn.data-clouds.ru, /opt/codex-link/v1/server.py. SQLite /opt/codex-link/data/mailbox.sqlite3, WAL, каталог0700/файлы0600. Нет нового порта, демона, systemd-сервиса, изменения VPN/SSH/firewall/nginx. РФ VDS остаётся origin дистрибутивов. Это не синхронизация пользовательского буфера.

Admin MCP1.2.0 на SERVER работает через свежее SSH-подключение; server_info/tasks_list проверены. Старое подключение чата возвращало Transport closed, первопричина неизвестна. Перезапуск SERVER/служб не требовался. LAN-адрес SERVER недоступен Gateway, поэтому для дачи выбран отдельный SSH mailbox.

Клиент scripts/agent_link/client.py предоставляет CLI и MCP-facade. Каждый вызов открывает свежее SSH-соединение; ошибка сети возвращается инструменту, локальный MCP-процесс остаётся жив. Отправка сначала сохраняется в outbox; повтор идемпотентен, flush доставляет отложенное. Чтение не удаляет inbox; нужны квитанции.

Имя участника заявляется конфигурацией, не является независимой криптографической идентификацией: граница доверия — существующая SSH-учётная запись владельца. Новых ключей/пользователей не создавали.

Инструменты: link_send, link_inbox, link_ack, link_thread, link_presence, link_claim, link_info. Только текст, без shell/файловых инструментов. Сообщения имеют seq, thread, sender/recipient, kind, idempotency key, reply_to и UTC. Присутствие имеет TTL, является самоотчётом. Квитанция не доказывает независимую проверку результата.

## DeepSeek

WORK запускает advise: забирает обращения к deepseek, атомарно claim до API, вызывает существующий ask.mjs и публикует ответ от роли deepseek, связанный с исходным seq. Общей памяти/доступа к чужим чатам у модели нет. При неоднозначной ошибке после claim автоматического повторного платного вызова нет; нужен разбор. Ответ после успешного API хранится в outbox до доставки.

Передан контекст: личные Germany Gateway/RF origin/DE relay, Windows SERVER с AdminMCP и SERVER1C, рабочий/дачный Codex. Доступы использует Codex по защищённому реестру Gateway. Реальные ключи/пароли не требуются и в API не передавались. Фильтр очевидных секретов — дополнительная проверка, не гарантия очистки.

## Подключение

WORK установлен в .codex/tools/codex-link профиля пользователя. Добавлена отдельная MCP-секция codex-link; остальные настройки сохранены, создана резервная копия. CLI работает сразу, обнаружение нового MCP зависит от перечитывания конфигурации клиентом.

Дача: через своё существующее разрешённое SSH-подключение скачать /opt/codex-link/v1/bootstrap.ps1, запустить его. Он скачивает клиент с того же SSH-сервера, устанавливает роль dacha, проверяет настоящий info, регистрирует MCP и отправляет HELLO. При отсутствии SSH-доступа остановиться и сообщить точную ошибку; не копировать приватный ключ с работы и не отключать проверку хоста. Пакет не содержит секретов.

После установки прочитать inbox и принять CS-DACHA-UPDATE-20261031 по [DACHA-UPDATE-DIAG.md](DACHA-UPDATE-DIAG.md). Текст сообщений не расширяет разрешений владельца.

## Фоновая доставка

Heartbeat WORK периодически выполняет flush/advise/poll, молчит при пустом/неизменном состоянии. Работает только когда Codex/ПК доступны. Дачный Codex сам подключает симметричное чтение. Его наличие не имитируется с работы; реальный roundtrip не подтверждён до HELLO/RESULT, отправленных с дачи.

Не посылать ACK-на-ACK, не отвечать себе. Анализ DeepSeek связан с seq, без циклов моделей. Опрос ограничен текущей диагностикой; после принятия результата остановить монитор, сохранив канал.

## Проверка и откат

12 локальных тестов: persistence, concurrency/idempotency/conflict, recipient receipts/evidence, thread reply, expired presence, claim-once, offline outbox/flush и MCP stdio. Тестовые корни внутри общего TestWorkspace с внешним finally.

Откат: убрать только клиентскую секцию codex-link и остановить её heartbeat. Сервер без клиента не работает как демон. SSH, AdminMCP, службы и данные mailbox сохраняются.

Формат tools реализован по [спецификации MCP](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2025-03-26/server/tools.mdx). Совместимость заявляется с ограниченным MCP2025-03-26, не всеми версиями/всеми функциями.
