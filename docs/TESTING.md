# Проверка ClipShot перед выпуском

## Автоматический запуск

Windows 11 x64, PowerShell 7, .NET SDK 10. Подготовка: `scripts/Setup.ps1`.

```powershell
# Быстрые независимые тесты, отчёт TRX
dotnet test ClipShot.Checks/ClipShot.Checks.csproj -c Release --logger trx

# Приложение, тесты и публикация
./scripts/Build.ps1 -Test -Publish

# Полная локальная проверка, включая установку и обновление
./scripts/Test-Release.ps1 -MakeNsis 'C:/path/to/makensis.exe' -PublishInstaller
```

Последняя команда копирует установщик в `D:/install/Codex Software/ClipShot-Setup-<версия>.exe` **только после успешной проверки**. Ключ `-SkipBuild` позволяет проверить уже опубликованные файлы. `-SkipDesktop` предназначен для CI без интерактивного рабочего стола; с ним публикация установщика запрещена. Прямой build-installer.ps1 компилирует пакет, но сам по себе не подтверждает прохождение тестов установки.

Каждый тест xUnit имеет независимую временную базу. Ошибка одного теста не скрывает результаты остальных. Тесты не читают и не копируют `%LOCALAPPDATA%/ClipNest/clips.db`.

`Test-Release.ps1` создаёт новый каталог `%TEMP%/ClipShot.Tests/<GUID>` для каждого запуска, проверяет код выхода и свежий отчёт. Ошибки UI/захвата возвращают ненулевой код. Результаты сохраняются в игнорируемой папке `TestResults/`: `core.trx`, текстовые отчёты UI/захвата/обновления и `release-checks.json`. Диагностика содержит только синтетические данные. Временные каталоги оставляются для диагностики после сбоя.

Установщик принимает `/TESTROOT=<TEMP/ClipShot.Tests/уникальная-папка>`: установка идёт в подпапку App, без реальных ярлыков и реестра. Завершается только тестовый экземпляр. Обычная установка продолжает пользоваться прежними путями и ключами ClipShot для совместимости. Тест повторной установки проверяет одну текущую версию поверх неё же; совместимость с каждой исторической версией этим не доказывается.

## CI

`.github/workflows/build.yml` запускает сборку, xUnit и проверку публикации на Windows при push/PR и вручную. Отчёты сохраняются как artifact. Интерактивные тесты WinUI и установка выполняются локальным сценарным прогоном; CI без рабочего стола не выдаётся за их замену. До отправки workflow в GitHub облачный CI не считается запущенным.

## Что остаётся проверить на устройствах

- Реальные Alt+F1/Alt+F2 и занятость клавиш сторонней программой; модификаторы проверяются автоматически, доставка WM_HOTKEY этим не доказывается.
- Передача текста/HTML/RTF/PNG между браузером, Office и другими программами. Тестовые режимы намеренно не меняют системный буфер.
- Несколько мониторов с разными DPI, RDP, блокировка/разблокировка Windows, сон и восстановление Explorer.
- Автозапуск, реальные ярлыки/реестр и переход с прежних выпусков — на отдельной Windows Sandbox/VM. Изолированный режим установки не меняет эти настройки рабочего ПК.
- Потеря питания, заполненный диск, антивирус, Windows SmartScreen и подпись. Цифровая подпись требует сертификата издателя; самодельная подпись доверия Windows не создаёт.
- Скорость интерфейса на большой истории и доступность экранному диктору. Проверка хранения 1200 записей не является измерением плавности интерфейса.

Процент покрытия всей программы не заявляется: xUnit проверяет вынесенную логику, а WinUI/Win32 и NSIS проверяются отдельными сценариями. Синхронизация остаётся отложенной. Семь тем проверяются отдельными UI-сценариями.

Основа тестов — [xUnit v3](https://xunit.net/docs/getting-started/v3/getting-started), результаты доступны через стандартный `dotnet test`.

## Регрессии 0.7.1

UpdateIdleTests проверяет порог пяти минут, сброс от ввода, неизвестный статус, переполнение тиков, отключённую автоустановку, видимое окно, незавершённую операцию и просроченный запрос завершения. UI-проверки: настройки → снимок → свернуть → открыть → снимок; редактор с разметкой → новый снимок → отмена → прежняя разметка сохранена. Проверяется одна строка всех девяти команд и подпись «Копировать в буфер».

Полный установочный тест проверяет отказ второго обновлятора и второго установщика без диалога, передачу блокировки дочернему NSIS, запуск после ошибки создания резервной копии, восстановление после ошибочного пакета и сохранность синтетической базы. Для проверки ошибки GetLastError в NSIS используется возврат ?e самого System::Call, как в официальном примере: https://nsis.sourceforge.io/Can_I_prevent_the_user_from_running_multiple_instances_of_the_installer%3F

Поиск снизу по умолчанию свёрнут в кнопку-лупу высотой 32 DIP. Только её команда открывает и фокусирует строку; закрытие очищает фильтр, повторный вызов панели не фокусирует TextBox. Боковая панель закрывается после копирования и при уходе в другое приложение; resize временно скрывает её и затем восстанавливает. Самоснимок не скрывает собственное окно и открытые настройки. Физическая проверка на устройствах со смешанным DPI остаётся ручной.
