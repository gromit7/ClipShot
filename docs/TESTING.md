# Проверка ClipShot перед выпуском

Владение временными каталогами, очистка после ошибок и безопасная параллельность: [жизненный цикл тестовых данных](TEST-DATA-LIFECYCLE.md). Полный gate включает реальную проверку этого механизма; ошибка очистки не должна превращаться в успешный выпуск.

Post-release публикация общей витрины и её изолированные проверки: [CATALOG.md](CATALOG.md). Тестовый этап не вызывает настоящий hook и не изменяет production.

## Ярлык рабочего стола 0.7.13

`Test-DesktopShortcut.ps1` компилирует общие с установщиком NSIS-функции и проверяет настоящие .lnk в отдельной временной папке: первая установка, обновление цели существующего ярлыка, два обновления после его удаления, переход с ClipNest с ярлыком и без него, восстановление зарегистрированной установки без файлов. Только последний случай использует собственный уникальный HKCU-ключ, который удаляется после проверки. Настоящий рабочий стол не затрагивается.

Полный gate дополнительно устанавливает реальный пакет в TestRoot: ярлык первой установки, сохранение при обновлении, отсутствие после удаления при двух следующих установках, включая `/AUTOMATIC`. Это проверяет место вызова функции до замены файлов, которое изолированный harness сам по себе не подтверждает. Меню Пуск и запуск приложения остаются прежними.

## Дополнения 0.7.11

- Legacy bridge принудительно задерживает ожидание runner на секунду после выхода setup в проверенном testRoot. Родительские SafeHandle должны быть открыты до ACK, чтобы ExitCode сохранялся даже после завершения процессов. После bridge.complete и ещё 1,2 секунды должен существовать ровно один живой тестовый ClipShot. Это отдельная проверка от ready-маркера/10 секунд внутри обновлятора.
- Повторная публикация допускается только для никогда не опубликованного draft с published_at=null и без существующего Git-тега. Повторная проверка перед upload обязательна; source target черновика сверяется с точным коммитом. Контракты запрещают перезапись public, ранее опубликованного draft и существующего тега.

- Изменённые снимки: сохранение исходных байтов/имени/даты/шаблона, перезапуск SQLite, установка дополнительной таблицы на прежнюю схему, отказ без частичной копии при ошибке транзакции, неизменённые и повторные результаты без дублей. Связи очищаются триггером при удалении, в том числе до повторного использования INTEGER PRIMARY KEY. История проверяет соседство исходника и последней правки через границу дней. Editor UI проверяет отдельный сохранённый результат, исходник, соседство и отсутствие записи в настоящий буфер в isolated-режиме.

- Background health проверяет не только marker, но и 10 секунд жизни нового процесса; unit-сценарии покрывают ранний выход после ready, отсутствие marker и приоритет выхода над уже существующим marker. Legacy migration на искусственных данных создаёт и закрывает настоящую плашку через общий renderer и проверяет отдельное подтверждение сохранения фонового процесса.
- Interaction проверяет сброс всех разделов/папок и предпросмотра при Hide, компактное повторное открытие после высоты 600 px и последующее явное раскрытие в обоих режимах. Отдельно проверяются отступ и направляющая дочерних клипов, сохранность drag targets и видимого содержимого при собственном захвате.
- Один пользовательский `ClipShot-<версия>.exe` обязан байт-в-байт совпадать с universal legacy-пакетом. D-fixture проверяет единственный итоговый файл, сохранение другого ПО, архив прежних имён и отказ при неверном архиве. Buildinfo/SHA256SUMS включают новое имя; mirror-fixtures проверяют публикацию четырёх имён для совместимости, несовпадающий hash и дубль canonical. Старые updater/feed-контракты остаются прежними.
- Эти проверки не устанавливают причину отдельного ночного выхода 0.7.10. Технический журнал ограничен двумя файлами и не содержит текста исключений, аргументов, буфера или имён документов.

## Автоматический запуск

Windows 11 x64, PowerShell 7, .NET SDK 10. Подготовка: `scripts/Setup.ps1`.

```powershell
# Быстрые независимые тесты, отчёт TRX
dotnet test ClipShot.Checks/ClipShot.Checks.csproj -c Release --logger trx

# Приложение, тесты и публикация
./scripts/Build.ps1 -Test -Publish

# Полная локальная проверка, включая установку и обновление
./scripts/Test-Release.ps1 -MakeNsis 'C:/path/to/makensis.exe' -PublishInstaller
```

Последняя команда копирует два установщика `ClipShot-Win10-Setup-<версия>.exe` и `ClipShot-Win11-Setup-<версия>.exe` в `D:/install/Codex Software/` **только после успешной проверки**. Ключ `-SkipBuild` позволяет проверить уже опубликованные файлы. `-SkipDesktop` предназначен для CI без интерактивного рабочего стола; с ним публикация установщика запрещена. Прямой build-installer.ps1 компилирует пакет, но сам по себе не подтверждает прохождение тестов установки.

## Аудит качества

Текущие решения об удалении дублей, усилении проверок и результат шести намеренных поломок: [аудит октября 2026](TEST-AUDIT-2026-10.md). Число тестов не является показателем полноты проверки.

Большинство тестов изолировано. Единственная проверка реального Core Audio только читает устройства и помечена `Category=Hardware`; её можно выполнить отдельно или исключить через `--filter "Category!=Hardware"`. Она не переключает микрофон. Синтетические HTTP-тесты не измеряют реальный интернет, а компиляция установщика не доказывает успешное обновление на ПК пользователя.

Каждый тест xUnit имеет независимую временную базу. Ошибка одного теста не скрывает результаты остальных. Тесты не читают и не копируют `%LOCALAPPDATA%/ClipNest/clips.db`.

`Test-Release.ps1` создаёт новый каталог `%TEMP%/ClipShot.Tests/<GUID>` для каждого запуска, проверяет код выхода и свежий отчёт. Ошибки UI/захвата возвращают ненулевой код. Результаты сохраняются в игнорируемой папке `TestResults/`: `core.trx`, текстовые отчёты UI/захвата/обновления и `release-checks.json`. Диагностика содержит только синтетические данные. Временные каталоги очищаются в `finally`, в том числе после сбоя, с проверенным сохранением технических отчётов в `.artifacts/test-diagnostics`. Занятые или небезопасные каталоги сохраняются с явной ошибкой очистки; подробности — в документе о жизненном цикле тестовых данных.

Установщик принимает `/TESTROOT=<TEMP/ClipShot.Tests/уникальная-папка>`: установка идёт в подпапку App, без реальных ярлыков и реестра. Завершается только тестовый экземпляр. Обычная установка продолжает пользоваться прежними путями и ключами ClipShot для совместимости. Тест повторной установки проверяет одну текущую версию поверх неё же; совместимость с каждой исторической версией этим не доказывается.

## CI

`.github/workflows/build.yml` запускает сборку, xUnit и проверку публикации на Windows при push/PR и вручную. Отчёты сохраняются как artifact. Интерактивные тесты WinUI и установка выполняются локальным сценарным прогоном; CI без рабочего стола не выдаётся за их замену. До отправки workflow в GitHub облачный CI не считается запущенным.

## Что остаётся проверить на устройствах

- Реальные Alt+F1/Alt+F2 и занятость клавиш сторонней программой; модификаторы проверяются автоматически, доставка WM_HOTKEY этим не доказывается.
- Передача текста/HTML/RTF/PNG между браузером, Office и другими программами. Тестовые режимы намеренно не меняют системный буфер.
- Несколько мониторов с разными DPI, RDP, блокировка/разблокировка Windows, сон и восстановление Explorer.
- Автозапуск, реальные ярлыки/реестр и переход с прежних выпусков — на отдельной Windows Sandbox/VM. Изолированный режим установки не меняет эти настройки рабочего ПК.
- Потеря питания, заполненный диск, антивирус, Windows SmartScreen и подпись. Цифровая подпись требует сертификата издателя; самодельная подпись доверия Windows не создаёт.
- Скорость интерфейса на большой истории и доступность экранному диктору. Проверка хранения 1200 записей не является измерением плавности интерфейса.

Процент покрытия всей программы не заявляется: xUnit проверяет вынесенную логику, а WinUI/Win32 и NSIS проверяются отдельными сценариями. Синхронизация остаётся отложенной. Семь тем проверяются отдельными UI-сценариями.

Основа тестов — [xUnit v3](https://xunit.net/docs/getting-started/v3/getting-started), результаты доступны через стандартный `dotnet test`.

## Импорт / inline / последние пять выпусков

Добавлены отдельные проверки декодирования full payload (без подмены preview), повреждений и ограничений памяти, read-only SQLite, отмены между строками, PNG/DIB и приоритета изображения над альтернативным текстом. Store-тесты проверяют исходные даты и повторный импорт, смешение истории с недатированными шаблонами, UTC-сравнение смещений, метаданные, отмену после SQL до commit, ошибку источника/целевого SQL и отсутствие target writer lock при декодировании.

Интерфейсный сценарий работает только с искусственными SQLite: открывает настоящий диалог, нажимает primary action через WinUI automation peer и сверяет шаблон, старую дату, retention и source hash. Геометрия проверяется на настоящем окне; история пяти выпусков — в настоящей плашке с ограниченной областью прокрутки. Ни системный буфер, ни личные базы не используются.

Независимый payload от запущенной Clipdiary в отдельной Sandbox/VM остаётся ручной межпрограммной проверкой. Unit fixtures, восстановленные по статическому формату, такой проверкой не выдаются.
