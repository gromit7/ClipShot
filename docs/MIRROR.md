# Обновления: российский origin и германский релей

## Адреса и доверие

- Origin: `https://bot.data-clouds.ru/clipshot/` (Россия). Здесь хранятся все версии, установщики, `latest.json`, постоянный ZIP и `update-feed.json`.
- Relay: `https://tg.data-clouds.ru/clipshot/` (Германия). Другой путь к тем же файлам, не отдельная публикация.
- Метаданные: `/update-feed.json`. РФ — единственный источник; DE проксирует его без кеша и без stale. Ответ `stable:null`, отзыв OS-варианта и аварийный rollback авторитетны. При валидном ответе или ошибке формата клиент не ищет более удобную старую ленту.

Проверка запускается при старте, затем раз в день в простое или вручную. Обычно один маленький GET к РФ; только сетевая/HTTP-ошибка либо deadline разрешают запрос через DE. Для пакета клиент пробует оба пути небольшим Range, выбирает быстрый, сохраняет докачку и обязательно проверяет точные размер/SHA-256. Признак включённого VPN не используется: важен реальный маршрут соединения при раздельной маршрутизации. Программа не меняет VPN, DNS или маршруты.

HTTPS и адреса закреплены. RF/DE не могут перенаправлять запросы на чужие сайты; имена версий/пакетов строго проверяются. Старый GitHub asset URL допускается только переходным резервом после ошибок обоих VDS. В приватном режиме publisher записывает RF URL — тогда GitHub в источниках клиента вообще отсутствует.

## Кеш DE

Версионные EXE кешируются nginx slice по 1 МиБ; HTTP Range работает и поперёк границы блоков. Лимит кеша 512 МиБ, LRU/неактивные блоки удаляются автоматически; это не удаление истории выпусков на origin. Прогрев всего EXE до начала скачивания не нужен. Версионные файлы неизменяемы и проверяются полным SHA.

Mutable `update-feed.json`, `latest.json`, `ClipShot-Latest.zip` никогда не кешируются. Ошибка origin не заменяется старой лентой. Шаблоны nginx находятся в scripts/nginx. Релей проверяет TLS-сертификат origin, включая цепочку; проверка сертификатов не отключалась.

## Публикация

`Release.ps1`: локальная проверка и GitHub CI → официальный выпуск → проверенные пакеты на RF → атомарная RF-лента → переходная GitHub-лента → актуальные два versioned OS-установщика в D:/install/Codex Software. DE получает файлы автоматически.

`Publish-Mirror.ps1` получает метаданные локальным авторизованным gh. Для закрытого репозитория локальный HTTP-клиент получает временные подписанные asset-ссылки; токен GitHub остаётся на ПК и не передаётся VDS. Временные ссылки не выводятся и не сохраняются скриптом. Приватный executor тоже не должен журналировать Command. Пакет на RF принимается только после сверки размера/SHA с официальными метаданными. Каталоги версий неизменяемы, последний ZIP/release JSON переключаются одной общей ссылкой current, старые версии остаются для отката.

`Publish-OriginFeed.ps1` проверяет все referenced EXE на RF, сохраняет прежний feed вне web-root и делает atomic replace точных UTF-8 bytes. CheckOnly не меняет origin. `scripts/origin_feed.py` не обращается к GitHub или сети. Ошибка хеша, схемы, версии или резервного копирования запрещает замену. Функции проверяются на искусственных каталогах в Windows и Linux.

Приватный исполнитель задаётся через CLIPSHOT_MIRROR_EXECUTOR и хранится вне репозитория; он получает Command и возвращает JSON receipt + ssh_exit 0. Секреты в исходники не входят.

## Переход и проверка

GitHub остаётся публичным, пока тестеры на старой 0.7.6: её жёстко заданная GitHub-лента ещё нужна. Сначала они должны получить переходный выпуск 0.7.7. Закрытие выполняется только после подтверждения перехода. Автоматического сбора версий тестеров и телеметрии нет.

Проверены на 0.7.6: RF/DE feed byte-identical, оба HTTPS; Range начала, конца и поперёк slice; MISS→HIT; полный Win11 SHA через DE дважды. В серверном замере первый проход 38,15 с, повтор 0,74 с. С рабочего Windows-ПК полный EXE 88254536 байт получен за41,16 с, SHA совпал. Прямой RF feed с этого маршрута дал timeout, DE ответил200 — настройки VPN не менялись. Это конкретные замеры, не обещание скорости всем пользователям.

## Откат

До nginx-изменений сохранены закрытые копии конфигураций на соответствующих VDS; nginx -t пройден до graceful reload. Откат DE: вернуть прежний tg site и убрать только созданные ClipShot include/cache directives; cached blocks можно оставить. Откат RF: вернуть прежний maxbot-api site; старые versioned EXE и current не удалялись. Feed восстанавливается atomic replace из закрытой предыдущей копии; приложение откатывается только явной политикой с affectedVersions и заранее проверенными пакетами. VPN, SSH, firewall и работающие прикладные службы не перенастраиваются.
