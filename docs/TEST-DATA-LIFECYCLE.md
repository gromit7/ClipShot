# Временные данные тестов

## Причина накопления

`Test-Release.ps1` создавал отдельные GUID-каталоги для интерфейсных проверок, языковых/OS проверок NSIS и установки. Его `finally` восстанавливал окружение и писал отчёт, но не удалял каталоги. `Test-LegacyUpdaterBridge.ps1`, `Test-WindowsRuntime.ps1` и тест ярлыка также оставляли свои данные. Несколько модульных тестов загрузчика, целостности установки и отложенного обновления вообще не освобождали созданные фикстуры.

Самые большие остатки — полная установленная программа, `App.ClipShot-backup-*`, `App.ClipShot-failed-*`, копии обновлятора и пакетов. Резервные копии нужны для проверки отката во время сценария, но не после завершения теста. Это не повод отключать резервирование в рабочем обновляторе.

## Владение и очистка

- Общая реализация — `scripts/TestWorkspace.cs`, PowerShell-обёртка — `scripts/TestWorkspace.ps1`. В модульных тестах используется `using`/`IDisposable`, в сценариях — внешний `finally`, охватывающий также подготовку и ошибки проверки.
- Каждый владелец создаёт только свой GUID-каталог непосредственно в `%TEMP%/ClipShot.Tests` и держит `.test-lease`. Никто автоматически не удаляет соседние или исторические каталоги.
- Проверяются абсолютная граница, родительские каталоги и внутренние reparse points. Junction/символические ссылки приводят к отказу очистки. Известный список удаляется без рекурсивного обхода; неожиданно появившийся файл сохраняется и мешает удалить его непустой каталог.
- Перед очисткой PowerShell проверяет процессы по пути/аргументам и зарегистрированным PID со временем создания. Последнее нужно для приложения, получившего путь только через окружение. Существующие приложения не завершаются ради очистки. Занятые файлы сохраняются, ошибка очистки видна в результате прогона.
- Технические отчёты `.txt`, `.log`, `.jsonl` и исходник NSIS сохраняются в `.artifacts/test-diagnostics/<запуск>/<каталог>`. Копия проверяется по SHA-256 до удаления оригинала. Ошибка сохранения удерживает исходный каталог. Базы, изображения и копии программы после будущих завершённых тестов удаляются: они синтетические и воспроизводятся кодом теста.
- `.artifacts` исключён из Git. Отчёты основного релизного сценария остаются также в `TestResults`. Большие старые материалы разовой очистки хранятся локально, не попадают в выпуск и не публикуются.

## Параллельность

Модульные тесты используют независимые корни. Полный интерфейсный сценарий, проверка Windows Runtime и legacy bridge берут общий `Local\ClipShot.TestSuite.v1`: существующие WinUI/legacy механизмы пока имеют общие имена. Второй процесс получает отказ до запуска окон. Вложенный сценарий того же процесса освобождает только свой уровень блокировки.

Это не попытка запускать два окна тестовой ClipShot одновременно. Параллельность файловых/модульных сценариев сохраняется; интерфейсные проверки безопасно сериализованы.

## Проверки

`Test-TestWorkspace.ps1` проверяет настоящий junction, сохранение отчёта с SHA, очистку при ошибке, неприкосновенность соседнего владельца, отказ второму процессу и сохранение данных ещё работающего процесса, даже когда путь передан только через окружение. Работает в PowerShell 7 и Windows PowerShell 5.1.

`TestWorkspaceTests` покрывает исключение с вложенными резервными копиями, параллельных владельцев, занятый файл, недопустимый архив, чужой путь и файл, появившийся после инвентаризации. Полный модульный прогон дополнительно сравнивается с перечнем временных корней до запуска: новых остатков быть не должно.

При принудительном завершении процесса, отключении питания или отказе диска `finally` не гарантирован. Такие остатки не удаляются вслепую следующим тестом: требуется отдельная проверка процессов, границ, ссылок и необходимости сохранения. Очистка не объявляется успешной, если остались занятые или непроверенные данные.

Рекурсивный API .NET не следует через reparse points ([Microsoft](https://learn.microsoft.com/en-us/dotnet/api/system.io.directory.delete)), но этого недостаточно для защиты новых файлов. Поэтому рабочий механизм удаляет только свой проверенный список, без рекурсивного удаления корня.
