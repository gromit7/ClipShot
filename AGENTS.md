# ClipShot — правила проекта

- Уточнение владельца от 28.10.2026: один пользовательский установщик для Windows 10/11, имя `ClipShot-<версия>.exe`, на D только один актуальный установщик ClipShot. Это заменяет прежнее требование двух OS-пакетов ниже. Совместимые имена пакетов для уже выпущенных обновляторов сохранять до проверенного перехода; опубликованные бинарники не изменять.

- Отвечать по-русски. Проект для Windows 10 x64 от 1809/build17763 (включая LTSC2019) и Windows 11 x64: C#, .NET 10, WinUI 3, SQLite. Функции и полезная нагрузка общие; совместимость не считать подтверждённой одним manifest или тестом установщика. Матрица и границы проверки — docs/WINDOWS-PACKAGES.md.
- При продолжении сначала читать `docs/STATUS.md`. Требования — `ClipShot/docs/requirements.md`; результаты проверок — `ClipShot/docs/verification.md`.
- До изменений: `git status --short`, затем при чистом дереве `git pull --ff-only`. Не перезаписывать незакоммиченные изменения. При параллельной работе использовать отдельную ветку.
- Подготовка нового ПК: `powershell -ExecutionPolicy Bypass -File scripts/Setup.ps1`.
- Проверка: `powershell -ExecutionPolicy Bypass -File scripts/Build.ps1 -Test -Publish`.
- Проверка интерфейса: опубликованный `ClipShot-app/ClipShot.exe --smoke-test`; захвата: `--capture-self-test`. Эти режимы используют только синтетические данные.
- Личная база `%LOCALAPPDATA%/ClipNest/clips.db` содержит буфер пользователя. Не читать, не копировать в репозиторий, не выводить содержимое. Не коммитить ключи, токены, настройки входа, установщики, bin/obj и кэши.
- Изменения интерфейса проверять на синтетических данных, при необходимости в светлой и тёмной темах. Не считать успешную сборку доказательством работы горячих клавиш или буфера.
- Основной результат теперь установщик. После согласованной публикации сохранять в `D:/install/Codex Software/` только один актуальный `ClipShot-<версия>.exe` без подпапок. Универсальный legacy-пакет нужен старым обновляторам и постоянной ссылке восстановления. Обновление ставится поверх старой версии с сохранением пользовательской базы.
- Перед завершением обновлять docs/STATUS.md. Публичный репозиторий: https://github.com/gromit7/ClipShot. Пользователь разрешил публикацию исходников и описания; перед push проверять отсутствие личных данных и секретов. Не выполнять force-push и не удалять старые репозитории.
- Синхронизация пользовательского буфера между ПК пока не реализуется. Git синхронизирует исходники проекта.

- Автотесты и выпуск: читать docs/TESTING.md. Перед выдачей релиза запускать scripts/Test-Release.ps1. Установщики хранить без подпапок, всегда с версией в имени. Не считать компиляцию пакета проверкой установки.
- Постоянное разрешение владельца от 27.10.2026: после завершённых изменений и успешного полного прогона самостоятельно выпускать следующую версию на GitHub, RF origin/DE relay, переключать автообновление и сохранять на D один актуальный универсальный установщик. Повторное подтверждение обычного выпуска не требуется. Закрытие GitHub по-прежнему ждёт подтверждения перехода тестеров на VDS; сетевые/SSH/VPN/firewall-изменения этим не разрешены.
- Режим работы от 27.10.2026: днём записывать фичи в docs/FEATURE-QUEUE.md; выполнять их по будням с 13:00 до 14:00 и после 18:00 Asia/Magadan (уточнение владельца от 29.10.2026). После 14:00 не управлять интерфейсом; незавершённые интерактивные проверки переносить на вечер. Автоматизация clipshot привязана к этому чату. До отдельного «делай сейчас» днём реализацию не начинать. Условия запуска, тишина при пустой очереди и ограничения интерфейса — docs/EVENING-WORK.md; читать при работе с очередью или расписанием.

- Перед полным release gate обеспечивать не менее8ГиБ свободного места C; при недостатке архивировать только собственные завершённые синтетические TestRoot на D:/Codex-Test-Archive, предварительно проверив границы путей, отсутствие junction/символических ссылок и работающих процессов и сверив SHA после перемещения. Пользовательские данные и другие каталоги TEMP не трогать; свежий результат/диагностику сохранять. Предпочитать сохранение тестовых артефактов, а не удаление.
